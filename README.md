# WROB · 英雄联盟手游赛事观赛（OB）系统

给民间赛事用的直播包装：BP 面板、局内比分条、野怪计时、对位经济差。项目背景、调研和设计见 [claude.md](claude.md)。

**现在能用的**

- BP 面板和导播台：队名、选手 ID、每一手 BP 由导播手填（不做自动识别）。
- 局内面板（参考 LPL 的样式）：顶部战队面板（系列赛比分、人头、团队经济、经济差、推塔、元素龙、时间），底部对位面板（出装、经济、KDA、对位经济差、阵亡与复活倒计时）。
- 画面识别：从数据机的 OB / 回放画面里实时读出比赛时钟、双方人头 / 推塔 / 团队经济、十个人的经济、KDA、六格装备、是否阵亡和复活倒计时、野怪击杀（元素龙是哪一方、什么属性；先锋、男爵、远古龙是哪一方），自动填进局内面板。

底部面板还会显示每个人的等级、两个召唤师技能、基石符文和大招：召唤师技能和装备进冷却时压暗并倒数，大招用掉后图标变暗、再一圈圈亮回来。双设备时每人还有血条（带护盾）和资源条，从数据机两侧的选手卡片上读。

**还没做的**：远古龙的击杀和红方拿龙还没有实际见过（见“画面识别 · 限制”）。

## 环境

项目用独立的 conda 环境 `wrob`，不动 base。里面有 Python 3.14、aiohttp、PyYAML、pytest、numpy、OpenCV、ffmpeg / ffprobe、scrcpy、adb。

```bash
conda activate wrob          # 每次新开终端先做这一步（VSCode 装了 Python 扩展的话，集成终端会自动激活）
```

换一台机器重建：

```bash
git clone https://github.com/DaRanSun/WROB.git
git clone https://github.com/DaRanSun/WRPedia.git
cd WROB
conda env create -f environment.yml     # Python 依赖 + ffmpeg
conda activate wrob
tools/install_scrcpy.sh                 # scrcpy 官方发行包（自带 adb），装进这个环境
```

WROB 是独立仓库；运行时需要 WRPedia 提供英雄、战队和选手资料。上面的命令会将两个仓库放在同一父目录，符合默认的 `config/app.yaml` 配置。录像、运行状态、截图和标注保存在本地 `data/`，不随仓库分发。

本机没有 Homebrew（装它要管理员密码），所以 ffmpeg 走 conda-forge，scrcpy 和 adb 用官方免安装包。以后要是装了 Homebrew，`brew install scrcpy` 也一样能用。

## 启动

```bash
conda activate wrob
cd WROB
python -m server                   # 状态中心 + 导播台 + 面板页面；自动打开导播台
```

要用画面识别的话，数据机用 USB 连上电脑，另开一个终端：

```bash
conda activate wrob
cd WROB
python -m vision                   # 识别服务：读数据机的画面，把数值发给状态中心
```

**两台手机同时接电脑**（一台观战机上屏，一台数据机给识别）：都用 USB 连上，`adb devices -l` 看各自的序列号和型号，然后分别指定——

```bash
python -m vision --serial 数据机的序列号 --record data/recordings/live.h264     # 识别只读数据机
scrcpy -s 观战机的序列号 --no-audio --video-bit-rate=16M --max-fps=60 --stay-awake --window-title=OB   # 观战机投屏，OBS 采这个窗口
```

数据机的序列号也可以写进 `config/vision.yaml` 的 `stream.serial`，以后就不用每次带 `--serial`。连着两台却没指定时，识别服务会列出两台手机让你选，不会乱读。

| 地址 | 用途 |
| --- | --- |
| <http://127.0.0.1:8780/director/> | 导播台 |
| <http://127.0.0.1:8780/overlay/bp.html> | BP 面板，OBS 浏览器源 |
| <http://127.0.0.1:8780/overlay/game.html> | 局内面板，OBS 浏览器源（2800×1264） |

`--port 8781` 换端口，`--no-browser` 不自动开页面，`--host 0.0.0.0` 允许局域网里另一台设备打开导播台（没有任何登录保护，只在可信网络里这么用）。

英雄图、队标、WRL 战队和选手资料直接读旁边的 `../WRPedia`，不复制；路径在 `config/app.yaml` 里改。

状态每秒存进 `data/state.json`，服务崩了或重启后原样恢复，面板会在一两秒内自己重连。撤销记录不落盘。

## OBS

两个面板各加一个**浏览器源**，背景是透明的。

- **BP 面板**：宽 1920、高 1080。下方 340px 是面板，上方留空给选手镜头或游戏画面。地址加 `?bg=1` 会铺满背景并显示对阵标题，没有别的画面可垫时用。
- **局内面板**：和手机画面一样大，宽 2800、高 1264（设成同比例的别的尺寸也行，比如 1920×867，页面会等比缩放）。观战机的画面全幅铺在下面，面板叠在上面，只有两样东西：
  - 顶部的战队面板：队标、队名、推塔、团队经济、人头；队名下面的小格是系列赛已经赢下的场数（BO3 两格、BO5 三格，BO1 不显示）；领先的一方在团队经济下面标出经济差；中间是“第几局 / BO 几”。第二行是比赛时间，两侧是双方各自拿到的元素龙（火、山、海三种图标）。
  - 底部的对位面板：五路各一行，从外到内是六格装备（最外面一格是鞋子）、基石符文、两个召唤师技能、英雄头像、选手 ID、经济和 KDA，中间是对位经济差和指向领先方的箭头。头像角上是等级。英雄阵亡时头像变成黑白，上面是复活倒计时。召唤师技能和装备在冷却时压暗，上面是剩余秒数。符文旁边是英雄的大招图标：五级之前不显示，转好了带一圈队伍颜色的亮边，用掉后整个变暗，再像表针一样一圈圈亮回来。

  观战机可以推不带任何界面的纯净画面；带着原生界面也行，这两块正好盖住原生的顶部条和底部面板的五行数据。
  男爵 / 远古龙 buff 生效期间，顶部面板下面对应队伍那一侧会出一块 buff 剩余时间和这段时间的经济收益（导播台“局内”页可以关）。野怪的刷新倒计时原生界面都有，面板不显示。
  顶部面板居中、宽 1600，不碰左上角的小地图。

  **两种画面模式**，开赛前在导播台“局内”页的“画面模式”里选：

  | | 单设备 | 双设备 |
  | --- | --- | --- |
  | 画面来源 | 只有一台手机，面板直接盖在它的画面上 | 观战机（Mac 上的 MuMu 模拟器）推纯净画面，手机当数据机给识别用 |
  | 画布（OBS 浏览器源的尺寸） | 2800×1264，和手机画面一样 | 1920×1080（或 2560×1440），16:9 |
  | 面板和画面的关系 | 面板盖在画面上 | 面板**不压画面**：顶部一条 0–90、底部一条 840–1080，中间 1920×750 留给纯净画面 |
  | 底部面板的内容 | 装备（含冷却）、符文、头像、选手名、经济、KDA、对位差。不显示等级、召唤师技能和大招——原生的选手卡片上看得见 | 全部：另外还有等级、召唤师技能、大招，以及血条和资源条。每行上面是选手名、KDA、经济（字更大；名字按最长 7 个字留位置，KDA 和经济各占固定宽度，五行上下对齐），下面是横跨这三栏的血条（带护盾）和资源条 |
  | 底部面板的大小 | 2175×406，正好盖住原生的底部面板和时间轴，不碰两侧的选手卡片 | 居中 1620×240，两侧各留 150 的空白（以后放多杀、连杀、数据对比、打龙的特效），用同色底条补满 |
  | 原生底部面板收起时 | 我们的底部面板跟着收起（打团时把原生面板收掉看视野，面板就自动让开），展开时再出来 | 不受影响（数据机的面板要一直开着） |

  **双设备怎么摆**（OBS 画布 1920×1080；用 2560×1440 时坐标都乘 4/3）：

  1. MuMu 的分辨率设成 **64:25（2560×1000 或 1920×750）**，画面放进中间那块正好不变形、不留黑边。（10-22 加血条之前是 32:13 / 1920×780，底部条加高了 30。）
  2. OBS 下面一层：MuMu 窗口采集，裁掉模拟器自己的工具栏，放在 x 0、y 90，大小 1920×750。
  3. 上面一层：局内面板的浏览器源，1920×1080，铺满整个画布。
  4. 导播台“局内”页的画面模式选“双设备”。

  双设备开播用 `./start.sh dual`（不开手机投屏窗口），**先启动它再打开 OBS**（OBS 的浏览器源打开时连不上面板地址就会一直空着，要手动“刷新当前页面的缓存”）。

  第 2、3 步可以让脚本写：退出 OBS 后运行 `python tools/setup_obs.py dual`，会新建一套场景集合和配置文件“WROB 双设备”（画布、输出都是 1920×1080，场景“局内（双设备）”和“BP”），单设备那套“WROB”不动；OBS 菜单“场景集合”“配置文件”里两套随时切换（两个都要切）。脚本已经按 MuMu 的窗口裁好了：顶上的标题栏和工具栏（“我的安卓”）裁掉 76 像素、底下的圆角裁掉 52 像素，再等比铺满中间那块。MuMu 每次重开窗口编号都会变，要双击“观战机画面”重新选一下窗口（裁剪不用动）。游戏声音要的话另加一个“macOS 音频采集”，选应用程序 MuMuPlayer。
  推流和录像用硬件编码（Apple，H.264）。软编码（x264）在这台 Mac 上和模拟器、游戏抢 CPU，第一次测试时丢了 44% 的帧，画面一直卡。MuMu 的窗口别整个被别的窗口盖住或者最小化（有的程序看不见时会降帧），游戏里的帧率设到最高。

  **两个上角**：单设备右上角是赛事标识（盖住原生的观战按钮）；双设备都在顶部那条底色里，左上角赛事标识、右上角比赛轮次（“赛事设置”的“阶段 / 轮次”，空着就不显示）。赛事标识默认是 `config/app.yaml` 的 `brand`（SUFE LOLM 26），导播台“赛事设置”里可以改文字，或者填一张图片（放进 `assets/brand/`，写 `/assets/brand/文件名`，有图就显示图）。野怪 / 龙魂播报在右上角那一块里显示 2.5 秒（`config/effects.yaml` 的 `hold.objective`），然后淡出、换回原来的内容；接连来的排队播。示意图在 `data/screenshots/角标/`。

  大小都在 `overlay/game.css` 开头：`--matchups-scale`（底部面板整体放大倍数）、`--matchups-width`，双设备的版式写在 `.stage[data-mode="dual"]` 那一段。
  位置和大小是 `overlay/game.css` 开头的变量。

  元素龙的图标用的是 `assets/dragons/` 里的图片：文件名以 `infernal` / `mountain` / `ocean` 开头就行（不分大小写，现在是 `Infernal_Dragon_buff.png` 这三张）。换图直接替换文件，刷新浏览器源生效；哪种属性没有图片，就用程序自己画的示意图标。

## 导播台 · BP 页

操作方式和 WRPedia 的录入后台一样：一页填完队名、选手 ID 和 BP。

**队伍**（页面上方，左边是本局蓝方、右边是红方）

- 简称、全称、五个选手 ID 直接打字，离开输入框就生效。
- “套用预设…”可以一键带出 WRPedia 里 8 支 WRL 战队（或 `config/teams.yaml` 里自己的战队）的队名、队标和首发。
- `−` `+` 改比分，两队中间的 `⇄` 交换红蓝方。
- 自定义队标在“赛事设置”页填。

**BP**（两侧各 5 个禁用位、5 个选用位，每个都是一个输入框）

- **打字**：中文、英文、拼音、首字母、昵称都能搜。`↑` `↓` 换选项，回车填入。
- **点选**：点输入框展开下拉，或者直接点中间的英雄格子。
- 填完自动跳到 BP 流程里的下一个槽位，所以可以“打字、回车、打字、回车”一路填下去。
- 禁用位下拉的第一项是“空 Ban”，也可以直接打 `kong` 回车。
- 下拉里常用英雄排在前面（按 WRL 的选禁次数）。本局已禁、已选、被无畏征召锁住的排在最后并写明原因，格子里是灰的；按住 Shift 再回车 / 再点可以强行填。
- **改错**：点任意一格重新选；把文字删空再离开 = 清空这一格；行尾的 `×` 也是清空；拖序号可以和同类槽位交换；`Ctrl/⌘ + Z` 撤销上一步。
- 不点“开始 BP”直接填第一格，会自动开始。“开始 BP”的作用是让面板上的倒计时在正确的时刻开始走。
- 勾上“先预选，回车再锁定”后，选英雄只是在面板上亮出来，再按一次回车才锁定（想把选手的预选也播出去时用）。

**自选模式**（OB 排位、巅峰对决这类不走赛事征召的对局）

- 开始之前在流程栏的下拉框里选“自选（不禁用，按顺序选，选完调分路）”，两边的禁用位就没了。
- 按游戏里的选人顺序填英雄（默认排位的蛇形顺序 B R R B B R R B B R，填完自动跳到下一格；可以跳着填、回头改）。**选人时不定分路**——排位里谁走哪一路要进了游戏才看得准。
- 十个都填完后和赛事征召一样进入阵容阶段：每个选用位后面出现“上野中下辅”，按历史出场预填了一套，对着游戏里的实际分路点正，再“确认阵容”“进入局内”。
- **开局之后发现分路不对**（比如女枪其实在下路、鳄鱼在上路），回 BP 页直接点改分路，局内面板上对应两路的英雄马上跟着换；识别是按游戏里的分路逐行读的，不受影响。
- 没有倒计时。同一个英雄不能两边都有（真遇到了按住 Shift 强行填）。无畏征召按“赛事设置”里的选项来，OB 排位这类不需要的对局在那里选“不启用”。

**3 Ban**（小组赛用）：流程下拉框选“3 Ban（双方同时暗禁 3 个，再按顺序选）”。

- 双方各 3 个禁用位，**同时开放**，先填哪边都行（游戏里亮出来后照着填）。暗禁互相看不见，所以两边可以禁同一个英雄；同一方不能禁两次。没禁的那一格点“空 Ban”。
- 禁完之后和自选模式一样：按选人顺序填英雄、选完对着游戏调分路、确认阵容、进入局内。任何一方禁掉的英雄两边都不能选。
- 不读秒。无畏征召照样按“赛事设置”里的选项：双边无畏时，前几局任何一方选过的英雄两边都不能选、也不能禁；只锁本队时只拦本队选过的。禁用会记进系列赛记录，赛后面板最下面显示。
- 要 5 Ban：在 `config/draft.yaml` 里照 `blind3` 抄一个，把 `bans: 3` 改成 5。

**BP 自动识别**（数据机停在游戏的选人界面时）

- 识别服务在跑、数据机进了选人界面，导播台的 BP 会自动填：禁用、选手“亮出”的英雄（面板上是一闪一闪的预选）、选定的英雄。流程（3 Ban / 赛事征召 / 自选）还是要导播先在下拉框里选好；没点“开始 BP”也会自动开始。
- 亮出和选定怎么分：游戏里看不出“锁定”那一下，所以按轮次——轮到某一方时它各行亮出的英雄都记成预选（换一个记一个），轮到另一方（或者进了准备阶段）时，最后亮着的那个记成选定。
- 禁用：顶部两角圆圈里出现的英雄就是禁掉的；暗禁两边禁同一个照样记。空 Ban 要等那一轮禁用结束（3 Ban 是“禁用显示”之后进了选人；赛事征召第一轮 3 个、第二轮 2 个各算一轮）还是“⊘”才记。
- **导播永远说了算**：导播自己锁过的格子识别不会改；识别填错了直接改，改完它也不会改回去。BP 页右上角的“识别自动填 BP”勾掉，识别的 BP 一概不收。
- 选手的分路识别不填（排位里谁走哪一路看不出来），选完照旧在阵容阶段核对、确认。
- 头像模板是你录的全英雄格子（`assets/bp-icons/`，142 个英雄），阶段标题和“⊘”的模板也来自那两段录屏。出了新英雄：`python tools/build_bp_icons.py extract 录屏.mp4`（只裁出模板里还没有的，人核对一下名字），再 `build`。

**阵容**

1. 双方选完后，每个选用位后面出现“上野中下辅”，已经按 WRL 历史出场预填好，点一下改正。
2. “确认阵容”：面板上的选用位按分路重排，并显示选手 ID。
3. “进入局内”把阵容带进局内面板。
4. 打完点“结束本局 · 某队 胜”（要点两下确认），和局内页的同名按钮一样，见下面“结束本局”。比分加一，本局选过的英雄进无畏名单，下一局默认败方在蓝方。

倒计时只是给观众看的参考，归零后不会自动跳过，一切以导播操作为准。和游戏一样，30 秒的一手在面板上从 29 数到 0：

| | 禁用 | 选人 | 阵容调整 |
| --- | --- | --- | --- |
| 3 Ban、自选 | 双方同时禁，共用一个 30 秒（之后“禁用显示” 5 秒） | 按 B RR BB RR BB R，每轮 25 秒，连选的两手共用 | 不读秒，导播核对分路后手动确认 |
| 赛事征召（5 Ban） | 一手一个，各 30 秒 | 一人一手，各 30 秒 | 不读秒 |

这是 10-20 录屏里游戏实际的读秒（3 Ban 的选人是 25 秒，不是 30）。识别在跑时，导播台和 BP 面板的倒计时直接对到游戏标题下面的读秒上（每跳一下对一次），游戏的读秒哪天改了也跟得上；没开识别时按 `config/draft.yaml` 里的秒数走（`seconds`、`ban_seconds`、`pick_seconds`、`order`、`lineup_seconds`）。
赛事征召里同一方连选两手时，标题不变、读秒重新从 29 数：识别看到读秒跳回去，就把上一手当时亮着的英雄记成选定。

## 导播台 · 局内页

开了画面识别时，时钟、人头、推塔、经济、KDA、装备、阵亡和复活倒计时都是自动的，这一页用来看识别状态、点野怪击杀，以及在识别出错时手动覆盖。识别运行期间手动改过的字段会自动锁住（橙色框），识别不再动它；“解除手动锁定”把它们交还给识别。底部面板上的英雄头像和选手 ID 来自 BP 页确认的阵容，不是识别出来的。

- **野怪**：开了识别时，野怪击杀是自动记的——元素龙带阵营、属性、时刻；先锋、男爵、远古龙带阵营和时刻。识别看不准是哪一方时（回放、底部面板收起、两边同时有事件），事件列表里会出现一条橙色的“××被击杀，是哪一方？”，点一下蓝方或红方（点上面那一行的按钮也一样）；击杀时刻用的是识别到的那一刻，不是你点的那一刻，所以 buff 倒计时是准的。识别报错了点 `×` 撤掉。勾上“野怪由我手动控制”后识别不再记野怪击杀。
  全手动时：谁拿下就点谁；小龙先在“属性”里选火 / 山 / 海再点，面板上才会是对应的图标。
- **装备**：每名选手六格，最外面一格是鞋子。点一格弹出装备库，打字筛选（回车选第一件）或直接点；“清空这一格”把它置空。手动改过后这名选手的整排装备会锁住，由你负责，直到解除锁定。
- **阵亡**：点“存活 / 阵亡”切换。识别在跑的时候按钮上会带着复活倒计时。

没开识别时全手动：游戏 00:00 那一刻点“从 00:00 开始”，之后人头、推塔、野怪击杀靠点按钮，时钟不准就“对表”。逐人经济、KDA、装备也能手填，经济填齐后自动算对位差。

## 结束本局 · 胜利画面 · 赛后面板

基地爆了之后，在“局内”页的“结束本局”卡片（或 BP 页底部）点“结束本局 · A 胜 / B 胜”，点两下确认。随即：

1. **自动记录**：比分加一、本局 BP 和经济曲线存进系列赛记录，BP 页换成下一局的空白槽位（默认败方在蓝方）。时长不填就用比赛时钟——识别在跑时取它最后一次看到游戏时钟的时刻，所以晚点几十秒也没关系；要手填就填在按钮旁边的“时长”里。
2. **识别立刻停读局内数据**：状态中心不再收识别发来的任何局内数据，识别服务也停止读局内的画面，改为等结算页。
3. **OBS 放胜利画面**：整个局内面板换成胜方的胜利画面（队标、VICTORY、系列赛比分、局数和用时；拿下系列赛时写“拿下系列赛胜利”）。
4. **读到结算数据才弹赛后面板**：数据机在结算界面点“统计”，停在底部“数据”、右上角“综合”这一页（“数据对比”，双方各 5 行：输出、总承伤、总治疗护盾、参团率、总经济）。识别读全、校验通过之后，OBS 换成赛后面板（版式照 `data/screenshots/结算/赛后面板参考.png`）：
   - 顶部：双方队名、WIN / LOSS、队标、系列赛比分，中间是本局时长和 BO 几；
   - 左边：双方的 K/D/A、经济（结算页的最终总经济）、推塔、峡谷先锋、元素亚龙（按属性）、远古巨龙、纳什男爵，下面是整局的经济差曲线；
   - 右边：十个人对英雄造成的伤害，条形图按全场最高的那个人缩放；卡片里的“右侧比较”可以换成承伤、治疗护盾或经济；
   - 最下面是双方的禁用（自选模式没有禁用，这一行不显示）。

   读不到（数据机没打开这一页）就一直停在胜利画面。胜利画面至少放 6 秒，数据读得再快也不会一闪就换掉。这一页打开时数字有约 1 秒从 0 往上跳的动画，**在这一页停两三秒**再翻走。
5. 卡片里会列出读到的十个人的数据供核对；“收起胜利画面 / 赛后面板”把它关掉（再点放出来）。下一局“进入局内”后自动清掉。

**点错了**（胜方点反、点早了）：BP 页的“撤销”（`Ctrl/⌘ + Z`）。比分、BP、赛后画面都回到点之前，局内也接着收识别的数据，然后重新点对的那个。

  - 价值表在 `config/loadout.yaml`：每件装备的商店总价，从游戏内商店截图（`../loadout value/`，18 张）里读出来、逐件核对过。进化装备（歌之权冠、炽天使之拥、芬布尔之冬、魔切、山脉壁垒、黑雾巨镰）按进化前那件算。价格随版本变就直接改这个文件，重启服务生效；名字写错了启动时会报错。
  - 装备库里每一件都有价值；识别认不出的（“?”）那一格保持原来那件，不会少算。
- **快捷键**：导播台在任何页签都能按 **E**（插入 / 收起经济曲线）、**T**（切入 / 切出团战 UI）、**L**（显示 / 收起装备价值），按键位认，不受中文输入法和大写锁定影响；光标在文字输入框里（BP 槽位、对表、装备筛选……）时不算，照常打字。按了会弹一条提示。
- **多杀以游戏自己的播报为准**：识别读画面上方的击杀播报（“红方二连破”“蓝方三连破!”），出现就放，时机和游戏一致。游戏接连播二连破、三连破就接连放（后一个直接顶掉前一个）；游戏用五连破“吞掉”了四连破，就直接放五杀。是哪名选手：这一方刚涨了人头的那一个；原生底部面板收起时（团战）读不到逐人人头，就放在这一方的半边，不写选手名。播报的模板来自录像（`tools/build_announce.py`），二、三、四连破都有真实样本，**五连破还没录到过**，“五”字是用系统字体渲染的——同一方刚播过四连破、下一条认不出数字时，也按五连破放。
- **自动 / 手动**：出装只认识别服务报上来的变化，导播手改装备不会触发；开一局、清空之后的几秒，以及单设备模式下原生面板刚重新展开的几秒（数字在补）不放。野怪播报在记上阵营时放（识别只看出“被打掉了”的那种，等导播点了阵营再放）。“特效”卡片的“自动特效”勾掉后只放手动点的；卡片里可以选一方一路手动放任何一种，用来预览美术、或者识别漏了时补上。
- **传说装名单**：`config/items.yaml` 的 `legendary`。里面有十几件我拿不准的已经标出来，请核对。

## 画面识别

**怎么接**：三个观战位里拿一台手机当“数据机”，USB 连电脑，打开 USB 调试。它的画面不上屏，只给识别用，所以要：

- 开局先把双方按上、野、中、下、辅排好；
- **底部面板全程展开**。收起后逐人经济和 KDA 读不到，面板上的逐人数据会停在收起前的值，团队经济自动改用顶部条的读数，导播台“局内”页会提示。

`python -m vision` 会在手机上另开一路视频流（10 帧/秒），和 `scrcpy` 投屏窗口互不影响，开不开投屏都行。

**读什么**：比赛时钟；顶部条的人头、推塔数、团队经济；底部面板十个人的经济（精确值）、KDA 和六格装备；两侧选手卡片上的阵亡状态和复活倒计时。每秒读 5 次，一帧约 9 毫秒。

- 结算页“数据对比”（导播结束本局之后才读）：先拿两半的表头和模板比，认出是这一页；再按空列把每格切成单个字，逐个和字形模板比（`vision/stats.py`）。读全之后要过校验：每一方的输出、治疗护盾、经济三组“数值 + 占全队百分比”必须互相对得上（百分比 ≈ 数值 / 五人之和，五人加起来 ≈ 100%），读错一位数几乎不可能还对得上；而且要连续三次读得一模一样（数字跳动动画最后一两帧的读数已经能对上，但还不是最终值）。模板来自两张截图（`data/screenshots/结算/`，`tools/build_stats.py`），用一张做模板读另一张、以及压成很糊的 JPEG、缩到一半再放大都全部读对；之前的录像里有 5 局拍到了这一页，表头相关 0.99，其余所有画面都不超过 0.15，读出来的数和画面逐项一致。
- 装备：把每个格子和装备库里的 176 个图标逐个比对。空格子、认出来了、认不准（主动装备冷却时整格被压暗）三种结果分开处理。
- 阵亡：原生界面里阵亡英雄的头像会变成灰色，上面压着红色的倒计时数字。头像本来就偏灰的英雄（蛮王、时光老人）不会被误判。
- 等级：选手卡片头像右下角的数字。数字是半透明地压在头像上的，个别头像上会读错或只读得出个位，所以按“等级一次涨一级、只涨不跌”的规律去抖和补全（见下面“怎么保证不出错”）。阵亡时原生界面不显示等级，面板保持阵亡前的数。
- 大招：头像上角的圆点（蓝方在右上、红方在左上）。没学大招时是暗的，转好了整块绿，冷却中是一块慢慢变大的绿色扇形——读的就是绿色占了多少，所以大招的冷却进度是直接从画面同步的，装备、符文让冷却突然变短也跟得上。大招图标来自 Riot 的公开素材库（`tools/fetch_ults.py`，141 个；诺拉端游没有，显示一个“R”）。
- 召唤师技能和基石符文：在两侧选手卡片上，头像旁边上下两个技能、下面一个符文。和图标库（`assets/spells/`、`assets/runes/`）比对。
- 血条和资源条：两侧选手卡片头像下面的黑框里，上面一条血、下面一条资源（蓝条 / 能量），都从左往右填，读的是填了多少列（`config/vision.yaml` 的 `bars`）。血平时是绿色，低血量时变成黄 / 橙、空的那段变成暗红（闪的时候亮红）；血后面接着的一段灰色是护盾，另外算。阵亡时整个黑框不显示，这时不读（面板上按空的画）。资源条按游戏里的颜色画（开局前一分多钟有的英雄是黄条，之后才变蓝）；锐雯这种没有资源条的英雄不画。只在双设备显示。
- 冷却：原生界面上，召唤师技能和装备用掉后图标会变暗，再像扇形一样慢慢亮回来。识别只抓“由亮转暗”的那一刻，从那一刻起按 `config/cooldowns.yaml` 里的时长读条，**读满为止**——原生图标亮回来的过程不会让读条提前消失。只有原生图标已经完全亮了 1.5 秒、而读条还剩超过 15% 时（冷却被技能急速缩短了，或者那一下其实不是用掉），才提前结束；最后那 15% 一律读满。
  - 召唤师技能的时长会按鞋子缩短：明朗之靴 15%，猩红明朗 20%。
  - “传送”在 6 分钟时变成“解封的传送”，两者共用一条冷却：图标换了，读条接着走。传送开局就在冷却，游戏时间 0:30 才第一次可用。
  - 惩戒是充能的，不读条，只跟着原生图标亮 / 暗。识别启动时已经在冷却的技能、图标库里叫不出名字的技能也一样，只压暗不倒数。
  - 装备只有冷却超过 6 秒的才读条（耀光、三相这类一两秒的被动不读）。
- 元素龙：原生顶部条上，一方每拿下一条元素龙，推塔数旁边就多一个图标（海龙青色、山龙土黄、火龙橙红）。图标一出现就记一次击杀，阵营、属性、时刻都有。
- 先锋、男爵、远古龙：小地图右边有两块原生的刷新牌子（上面一块是先锋 / 男爵的坑，先锋的图标是粉色、男爵是紫色；下面一块是小龙 / 远古龙的坑），写着“存活”或刷新倒计时；野怪被打掉的那一刻牌子消失。所以“存活”的牌子不见了就记一次击杀。
  是哪一方打的看底部面板上方的事件时间轴：红方的事件在上面一行，蓝方在下面一行；实时 OB 里新事件的图标出现在时间轴最右端，哪一行**突然**多出一个图标就是哪一方（另一方早先的图标在旁边慢慢挪动不算）。回放的时间轴一开始就画着整局的事件，这个办法用不上，回放里这三种野怪的归属要手点。

**怎么保证不出错**

- 同一个值连续读到两次才提交；经济、击杀这类只增不减的量读到下降，要持续约两秒才认（真的变小只有新开一局或回放往回拖）。
- 经济突然涨得离谱而 KDA 没变（多读了一位），或者五人之和与顶部条差出一千多，这次读数作废。
- 装备格连续两次认成同一件才换；认不准时保持原来那件；从“有装备”变成“空”要持续约两秒才认（卖掉、合成才会这样）。
- 复活倒计时连续两次一致才认；倒计时还剩不少却突然读成“活着”（头像被技能特效盖住），要持续一秒才认。
- 等级连续 1 秒读成同一个数才认；一下子涨三级以上要 3 秒；变小（开局调对位时两行换了人）要稳稳 5 秒。已经九级以上时只读到个位 0–5，按十几级算；读到 4 / 14 而 1 / 11 正好是现在或下一级时按 1 / 11 算（带小尖角的“1”在暗一些的头像上像“4”）。
- 元素龙图标要持续 1 秒才认；“存活”的牌子要消失约 1.6 秒才认。归属只在时间轴上恰好一方多出图标时才下结论，说不准就留给导播。回放被拖动、快进（时钟对不上）的那几秒不看野怪。导播已经手点过的击杀不会重复记；导播把某条龙记给了另一方，识别不会改回去。
- 时钟平时由状态中心自己走，识别只在偏差超过约半秒、暂停、恢复、回放被拖动时重新对表。时钟后面的地面太亮时（整块都成了“墨迹”）这一帧不读时钟；一下子跳 30 秒以上要连续 1 秒都读成那附近才认。以前背景太亮时会把时钟读成 22:22，状态中心跟着对了表。
- 血条前后两次读数差不多才算读稳（掉血的那一下前后两帧能差一大截，等下一帧）；和报过的差 2% 以上才报，十个人一起报，最多每秒 5 次（打团时十个人的血一直在变）。资源条的颜色连续 5 次一样才换。面板上血条掉下去时会留一截浅色，停一下再追上去，和游戏里一样。
- 导播在“局内”页手动改过的字段、勾了“时钟由我手动控制”的时钟，识别都不会再动。
- 每两秒和状态中心对一次账：导播中途点了“进入局内”或“清空局内数据”，时钟和各项数值会自动补回来。

**实测**

- 录像（一段 9 分钟的回放，每秒 5 次共 2700 次取样）：逐人经济读出率 99.76%，KDA 100%；五人击杀之和与顶部人头一致 99.75%，五人经济之和与顶部团队经济一致 97.9%——不一致的那些是顶部条比面板晚刷新一拍，不是读错。时钟读出率 97%，读出的全部逐秒递增。
- 同一段录像里的装备和阵亡：16.2 万次装备格读数里认不准的占 0.8%（都是冷却中的主动装备，面板上保持原样）；三帧抽查共 180 格，逐格对图全部正确。全部 25 次阵亡都读成了一条逐秒递减到 1 的倒计时，没阵亡过的三名选手没有一次误报。装备和阵亡**还没有在真机实时对局上跑过**。
- 血条（10-20、10-19 两段实时录像，每 0.5 / 1 秒取一帧，共 3.7 万次“活着的人”的读数）：读得出的占 99.9%（读不出的是镜头扫过、卡片被挡住的零星几帧）；阵亡时黑框不在，没有一次被地图当成血条。九种样子（满血、残血绿、低血量黄底暗红、闪红、护盾、阵亡、能量条、没有资源条、红方）放大逐列量过，读数和画面差不到 2%（低血量闪红的那几帧血和底色分不太开，只保证读出来很少）。把这段录像按原速喂给识别服务，面板上的血条跟着画面走，每秒更新约 5 次。**还没在真机实时对局上跑过。**
- 召唤师技能、符文和冷却（两段录像）：二十名选手的技能和符文都认了出来。读条的时长和画面上实际变暗的时段对得上：闪现 150 秒、幽灵疾步 90 秒、治疗术 100 秒，同一个人买了明朗之靴后治疗术变成 85 秒、换成猩红明朗后 80 秒；装备里视界专注 12 秒、破败王者之刃 30 秒。这部分**还没有在真机上实跑过**。
- 等级和大招（第二段实时 OB 录像）：十名选手的等级从 1 级到 12–15 级都是逐级上升的，16:45 那一帧和原生画面逐个核对一致；读出率因头像而异（56%–100%），薇恩的头像最差。有两处一两级的小波动（开局调对位的那一分钟、薇恩 6 级前后）。大招进度没有逐次核对，只看过几帧和原生圆点对得上。**还没有真机实跑。**
- 同一段录像里的野怪：蓝方两次拿龙（07:39 海龙、12:19 山龙）都认对了阵营、属性和时刻，按“击杀后 4 分 15 秒刷新”推出的下一条龙的时间和原生牌子上的倒计时一致；全程没有误报，包括结尾拖动回放的那一下。这段回放里红方没拿过龙、男爵没被打过。
- 实时 OB 录像（`live.h264`，一整局人机，00:57 到 16:50）：红方先锋（07:09）、蓝方两次男爵（11:29、15:57）、蓝方两条龙（07:47 火龙、12:34 山龙）全部认对了阵营和时刻，没有误报。这一局实跑时先锋漏了（当时不认识先锋牌子的粉色图标），男爵只报了“被打掉”；现在的结果是修好后用录像重跑的。时钟读出率 91%，比回放低（实时 OB 的镜头更常扫过亮的地方），不影响计时。
- 第二段实时 OB 录像（`live-1012-204716.h264`，00:00 到 19:00）：红方先锋、红方三条龙（海、山、火）、红方两次男爵。实跑时第二条男爵的归属没判出来（蓝方十几秒前的图标还在时间轴最右端附近，干扰了判断），改成只认“突然出现”之后重跑，六次击杀全对。红方龙图标的位置（之前是按蓝方镜像推的）在这一局得到了验证。传送 → 解封的传送的换图标和共用冷却也对。
- Power play（打龙收益）：击杀男爵的瞬间，击杀方每人到手一笔赏金（四次男爵击杀里都是每人 +120，补最后一刀的人再多 80–140）。收益的起点取的是击杀前 2 秒的团队经济，所以这笔赏金算在收益里。四次击杀时击杀方五个人都活着，**阵亡的队友拿不拿得到这笔钱还没有见过**；不过收益是按实际到账的经济算的，不管规则是哪种都不会算错。
- 真机（一整局，从 00:00 到 21:26，共 8260 次取样，当时还没有装备、阵亡和野怪识别）：全程没有重新对过表，终局双方逐人击杀之和都等于顶部人头。期间出现过 7 次把“4”读成“1”的错读，每次不到一秒，之后已经针对性修掉（见 `vision/text.py` 里的 `MAX_SOLID`）。

**限制**

- 标定是按荣耀 PTP-AN00（2800×1264）做的。宽高比相同的手机会自动缩放；宽高比不同的要重新标定 `config/vision.yaml` 并重建字形模板。
- 游戏更新改了观战界面的布局或字体，也要重新标定。
- 游戏出了新装备或改了装备图标，要更新装备库（见下面“装备库”）。库里没有的装备只会被认成“认不准”，那一格不显示，不会认成别的。
- **远古龙的击杀还没见过**：它的牌子见过了（17:30 出倒计时、19:00“存活”，图标颜色不在已认识的几种里，按“下面那个坑、19:00 之后”判断为远古龙），但那一局刚好在 19:00 结束。18:30 场上还留着小龙时牌子怎么变也没见过。
- 开局倒数阶段（游戏内计时从十几秒倒数到 0）时钟是倒着走的，面板上的时钟这十几秒会跟着跳；0:00 之后正常。
- 传送开局的冷却显示不出来：它暗着的时候认不出是传送，面板上要到 0:30 它亮起来才出现这个技能，之后正常。
- 先锋 / 男爵 / 远古龙的归属靠时间轴，所以数据机的**底部面板要展开**（时间轴和它一起收起）；回放里认不出归属。
- 识别是中途才启动的话，启动前已经拿下的元素龙会按“启动那一刻”记时刻，下一条龙的刷新计时会不准（属性和阵营是对的）。
- 层数这类装备上的角标不读（面板上也不显示）。
- 技能和符文的图标库来自掌盟截图：召唤师技能 10 个（含“解封的传送”），基石符文 13 个。两段录像里出现过的 8 种技能、11 种符文都认对了；虚弱、净化、传送和先攻、守护者两个符文还没在对局画面里见过。游戏出了新的技能或符文，库里没有时面板上那一格是空的，补法见下面“技能和符文的图标库”。
- 卖掉或挪动一件正在读条范围内的装备时，那一格可能闪一两秒的冷却读条（格子变空也是“由亮转暗”），之后自己消失。

**装备库**

装备的名字和图标来自掌盟“资料 → 物品”页的截图（现在这份在 `../Equip(raw)/`，13 张）。名字按截图顺序写在 `config/items.yaml` 里，它同时是装备的编号和图标文件名；`exclude` 里是对局中不会出现在装备栏的（潜行药剂）。

```bash
python tools/build_items.py "../Equip(raw)"      # 截图 → assets/items/*.png（面板用）+ vision/templates/items.npz（识别用）
```

游戏更新后：重新截图 → 把新装备的名字按位置插进 `config/items.yaml` → 重跑上面这条命令 → 重启服务和识别。名字和图标数量对不上时脚本会报错，不会悄悄错位。

只补一两件新装备时不用重截全部：把它在掌盟里的图标截一张（白底上一个圆形图标，旁边带着名字也行），放进 `../Equip(raw)/补充/`，在 `config/items.yaml` 的 `extra` 里写上“名字: 图片路径”，再重跑上面这条命令。现在有一件：放血者的诅咒。别忘了在 `config/loadout.yaml` 里给它写上价值（传说装还要加进 `legendary`）。

个别装备在游戏里的图标和掌盟的不一样，会一直认不出（面板上那一格空着，导播只能手填）。比如卡莉斯塔出的破败王者之刃：游戏里的图标构图和掌盟的不同，匹配分只有 0.60，差一点够不上。遇到这种情况，从录像里把那一格裁下来，当这件装备的“变体”：

```bash
python tools/item_variant.py add data/recordings/x.h264 --at 345 --cell red.3.5 --name 破败王者之刃
```

`--at` 是录像里的秒数（挑这件装备没在冷却、完整亮着的时刻），`--cell` 是哪一格（`red.3.5` = 红方第 4 行（下路）由外到内第 6 格，0 是鞋子）。裁下来的图存在 `assets/items/variants/`，模板在 `vision/templates/items-variants.npz`，重启识别生效。一件装备可以有几个变体，识别时取最像的那个。现在有一个：破败王者之刃。

**技能和符文的图标库**

和装备库一样来自掌盟“资料 → 技能 / 符文”页的截图（现在这份在 `../spellrune/`，7 张）。名字按截图顺序写在 `config/icons.yaml`，同时是编号和图标文件名；召唤师技能的名字要和 `config/cooldowns.yaml` 里的一致才有读条。

```bash
python tools/build_icons.py import ../spellrune     # 截图 → assets/spells/*.png、assets/runes/*.png + 识别模板
```

截图里没有的图标（比如“解封的传送”）从对局画面里裁：

```bash
python tools/build_icons.py cut data/recordings/live.h264 --at 636 --out ~/Desktop/icons    # 把某一刻十个人的技能、符文都裁出来
python tools/build_icons.py build                                                           # 改了 assets/spells、assets/runes 之后，重做识别模板
```

挑没在冷却的那一刻，把裁出来的那张 33×33 小图改成它的名字放进对应文件夹，运行 `build`，重启识别。

## 配置

| `vision.yaml` | 画面识别：各个数字、装备格、选手卡片、元素龙图标、野怪刷新牌子在画面上的位置，取样频率 |
